# 打开面板时的行为：落笔、脱 `<u>`、撤销键的禁用态

这份报告对应两次提交：`23775de`（行为改动 1–4）与 `19bb2e0`（视觉改动 5）。
改动全部来自真实测试里的三条观察：点色块会把选区/浮动工具栏/面板一起弄没；
打开面板时开关亮着、`solid` 选中而文档里没有下划线；原生取色器本身工作正常。

---

## 1. 哪些控件收面板，哪些不收

面板里的控件分成两类，判据只有一条：**这次点击之后，同一次选择上还有没有事情可做。**

| 控件                  | 收不收面板 | 为什么                                                                                                           |
| --------------------- | ---------- | ---------------------------------------------------------------------------------------------------------------- |
| 线型色块（5 个）      | **不收**   | 同一次选择上还要接着调颜色、接着看效果。收一次就得重新选中一次。                                                 |
| 颜色色块（11 个预设） | **不收**   | 同上。                                                                                                           |
| 跟随文字色色块        | **不收**   | 同上。                                                                                                           |
| 临时自定义色色块      | **不收**   | 它是「当前正在用的那个颜色」，点它仍是一次提交，但提交之后没有下一步了 —— 换色要自己去点另一块。                 |
| 方向开关              | **不收**   | 开与关都只是同一条下划线的一个参数，切换之后用户多半还要回去调线型。                                             |
| 清除装饰              | **收**     | 终止类。做完整段选区已经没有装饰，面板上剩下的每一个控件都只会给出「空操作」。                                   |
| 撤销                  | **收**     | 终止类。撤销把文档退回上一步，面板显示的那份配置已经不是文档的样子，继续调会改到用户没想到的那一步。             |
| 原生取色器            | **收**     | 终止类，且是唯一一条连选区带浮动工具栏一起交出去的路径：系统取色对话框强制拿走焦点，编辑器与浮动工具栏都已收摊。 |

浮动工具栏任何情况下都不由面板收：它归思源自己的收起流程（`subElementCloseCB`）。

实现上的落点只有一个：删掉 `activate()`（先提交再 `onClose`），设置类控件一律走 `update()`
（`src/panel.ts:711`、`715`、`717`、`720`），终止类控件自己显式调 `options.onClose()`
（取色器 `src/panel.ts:728-732`、清除 `src/panel.ts:734`、撤销 `src/panel.ts:744`）。
`onClose` 的字段注释也改成了「只由终止类控件、面板外的点击与 Esc 请出」。

## 2. 打开面板时的落笔，怎么走 `applyDecoration`

### 判定

`applyAtOpen`（`src/index.ts:242`）在 `openPanel` 里、`createPanel` 之前被调用一次：

```
dropNative = 选区里有没有思源自己的 <u>
if (!dropNative && (选区已经装饰 || 面板这份配置是关着的)) → 一个字节都不动
else → applyDecoration(面板这份配置, {dropNativeUnderline: dropNative})
```

三条分支对应三种情形：

* **选区里已经有下划线**（含「只有部分区域有」的混合选区）→ 只显示设置，`beforeHTML` 根本不会被写。
* **选区里没有下划线，且面板这份配置是开着的** → 真的应用（默认实线 + 跟随文字色，或上次用过的那份）。
* **记住的配置本身是关着** → 不应用。那是用户上一次点开关关掉时留下的明确决定，
  打开面板不该替他重新打开；此时开关显示为关，线型与颜色仍摆着，一点开关就沿用上去并真的落盘。

### 为什么走同一条路

`applyAtOpen` 自己不碰 DOM，它把活交给 `applyDecoration`（`src/index.ts:266`）：

* 偏移校验（`claimBlocks()` + `offsetsWithinContent()`）在同一个位置、同一条消息；
* `<u>` 的脱除与装饰的包裹合成同一次改动，因此只落一次盘、撤销栈里只占一条；
* 走同一个防抖保存器，因此打开时的这一次改动与用户随后点出来的那一次落在同一个窗口里合并，
  一个块仍然只发一次 `updateBlock`；
* `restoreOffsets` 会重建选区并聚焦，用户接着输入与面板的下一次改动都还有坐标可用。

### 记下偏移越界时用户看到什么

`applyDecoration` 的那道闸对打开面板这一次的落笔一样生效（`src/index.ts:268-276`）：
`claimBlocks()` 失败或 `offsetsWithinContent()` 为假 → `showMessage(i18n.selectionChanged)`
（中文文案：`选中的内容已经变了，未做改动；请重新选中后再试`），**文档一个字节都不动、`<u>` 也不会被脱**，
面板照常开起来（它摆的仍是那份没被应用的配置），用户重选一次再点工具栏即可。

真实思源里这一刻几乎不会发生：偏移是在同一个 `openPanel` 调用里刚从活着的 `Range` 记下的，
记下与应用之间没有任何会改 DOM 的步骤。测试是用白盒替身把它摆出来的（见下文用例清单）。

### 有没有重复保存

没有。`closePanel` 里的两步互不相干，也不会互相叠加：

* `this.saver.flush()` 是**那一次**待发保存的发送口，一个块一条 `updateBlock`；打开时的应用已经排在它里面了，
  flush 不会因此再发一次。
* `saveDecoration(this.appliedDecoration)` 写的是插件自己的 `settings.json`（记住上次用过的配置），
  与块保存不是同一个通道。打开时的应用把 `appliedDecoration` 填上，因此关闭面板时记住的正是刚应用的那一份。

一次用户动作（打开面板、或点一下色块、或关一次开关）= 一个块一条 `updateBlock` + 撤销栈里一条记录，
这条由「打开面板时选区里没有下划线：…并恰好发一次 updateBlock」与
「面板开着把下划线关掉再打开：两次都真的落到文档上，各发一次 updateBlock」两条用例钉住。

## 3. 思源自己的 `<u>`

### 作用域

`nativeUnderlineElementsIn`（`src/dom.ts:425`）与 `stripNativeUnderlineIn`（`src/dom.ts:448`）
都只在**调用方给的那一个可编辑区域**里 `querySelectorAll("u")`，再按**字符偏移的重叠**过滤。
它复用的是从 `decorationSpansIn` 里抽出来的那一份判据 `overlappingElements`（`src/dom.ts:360`）：

```
spanStart < range.end && spanEnd > range.start
```

不用 `Range.intersectsNode` 的理由与原来一样，写在 `overlappingElements` 的注释里：那条谓词不对称 ——
范围终点与元素起点相接不算相交（安全），范围起点与元素终点相接**算**相交，于是「从一个下划线词之后开始选中」
会把范围之外的标记当成在选区内，脱掉之后一去不回。抽出来共用，两条路径不可能对同一段文字给出相反的答案。

因此：**同一个块里落在选区之外的 `<u>` 不动，别的块、别的可编辑区域里的 `<u>` 不动**
（`querySelectorAll` 的根就是各自的区域，跨区域根本不会出现在候选里）。用例
「只有落在选区里的 `<u>` 被脱掉，同一块里其余位置的 `<u>` 逐字节不变」与
「另一个块里的 `<u>` 完全不在作用域内」各钉一半。

### 三种覆盖情形的取舍

* **完全在选区内**：整条脱掉，文字进插件的装饰 span。
* **与选区相交但没被盖住（半个 `<u>`）**：**整条脱掉**。行内元素没法按字符偏移切成两半，
  留半截又会让选区内那部分与插件的装饰叠成两条线 —— 那是用户更没法调的一种状态。
  取舍是：落在选区之外的那半截一并失去这条标记。这与「打开面板就是要把这段文字的下划线交给插件统一管」是一致的。
* **`<u>` 与插件装饰同时存在**：`<u>` 让位，插件那份装饰**按同一份配置重裹一遍**。
  装饰身份、线型与颜色都不变（`aria-pressed` 仍指向原来的线型与颜色，不报混合），
  但落盘形态会从思源渲染出来的 `span[data-type="text"][style]` 变成插件写出的 `span[style]` ——
  这与插件任何一次改动之后的样子相同，思源存盘时会把 `data-type` 补回去。
  为什么还是重裹一遍：脱 `<u>` 与应用装饰必须合成**同一次改动**（一条落盘、一条撤销记录），
  而「只脱不裹」需要另一条保存路径，代价是打开面板变成两次保存、两次撤销。

### 与「记住的配置是关着」这一档的合成

`<u>` 的脱除与「要不要把下划线打开」是两件事：无论配置开关如何，`<u>` 一定脱掉（插件接管这段文字的下划线了），
但配置是关着的时候不铺装饰。用例「记住的配置关着时：`<u>` 仍然脱掉，但不会被顺手打开下划线」钉住这一档。

### 与装饰脱除的关系

`stripDecorationIn`（清除装饰那条路）仍然不碰 `<u>`：`<u>` 不是插件的装饰，
`isDecorationSpan` 只认 span。脱 `<u>` 只有一个入口 —— 打开面板那一步。
既有用例「思源自己的 `<u>` 不算插件装饰：面板读不到，清除也不会碰它」因此继续成立。

## 4. 撤销键的禁用态

**为什么只有它是例外。** 设置类控件每一下都是新意图：点它一定产生一次改动，
哪怕「重复点同一个色块」被 `commit` 挡掉，那也是「没有新意图」而不是「按了没反应」。
撤销不一样：栈空的时候按它**什么也不会发生**，而亮着的按钮会让用户反复去按它 ——
那正是用户说的「按了没反应的控件」。所以它是唯一允许有禁用态的控件。

**怎么表达。** 控件是不可聚焦的 `div`，没有 `disabled` 属性可设，因此语义与外观**共用** `aria-disabled="true"`
这一个属性（`src/panel.ts:565` 的 `markDisabled`）：

* 语义：读屏软件读得出「此刻不可用」；
* 外观：`src/index.scss:148` 的 `[data-sue-panel] [data-sue-action="undo"][aria-disabled="true"]`
  给 `opacity: 0.5` + `cursor: default` + `pointer-events: none`（悬停反馈也一起停掉，
  与浏览器里 `disabled` 按钮的手感一致）；
* 拦截：按下时那条监听里再问一遍状态（`src/panel.ts:747`），禁用中既不调 `onUndo` 也不收面板 ——
  即使样式被用户的自定义 CSS 覆盖掉，行为也仍然正确。

**状态从哪来。** 撤销栈只有 `src/index.ts` 掌握（`persist.ts` 的 `hasUndoableChange`）：

* 打开面板时 `undoEnabled: hasUndoableChange()`（`src/index.ts:213`）；
* 每次改动之后由 `syncPanel` 一并刷新（`src/index.ts:425`）；
* 撤销成功之后同样刷新；撤销**失败**（栈空或剩余记录全部过期）时也刷新一次（`src/index.ts:317`）——
  那条路文档没变、面板不重画，但按钮此刻确实按不动了，不刷新就会一直亮着；
* 面板另给一个 `setUndoEnabled`（`src/panel.ts:794`）供调用方单点更新。

**没报时怎么办。** `options.undoEnabled !== false`（`src/panel.ts:588`）：面板自己不知道栈里有没有东西，
没报就按「有东西可撤销」处理，免凭空摆出一个按不动的按钮。`src/index.ts` 永远显式上报。

## 5. 线型色块的深浅

**落在哪。** 线型色块的示例线是元素自身的文字画出来的，`panel.ts` 写的是
`text-decoration: underline <style> currentColor`，因此线色完全由 `color` 决定 —— 深浅只能落在 `color` 上：

```scss
[data-sue-panel] [data-sue-style] {
  color: var(--b3-theme-color-lighter, #999);
}
[data-sue-panel] [data-sue-style].sue-swatch--selected {
  color: var(--b3-theme-color, #333);
}
```

两档都取自思源的主题变量（每档另带一个不透明兜底色），深浅主题各自跟随：
浅色主题下选中是 `#333` 一档的深、未选中是更浅的灰；深色主题下 `--b3-theme-color` 更亮、
`--b3-theme-color-lighter` 更暗，「更深」翻译成「更显眼」，两档照样分得开。

**没有把选中那一块做成不可点。** 深浅只是「它已经是当前线型」的说明，因此：

* 不加 `disabled` / `aria-disabled`（`markDisabled` 只作用在撤销键上）；
* 不关 `pointer-events`、不给 `not-allowed` 指针、不藏鼠标指针 —— 选中那一块照样有 b3-button 的悬浮反馈；
* 原来那圈外侧指示色（`box-shadow`）保留：深浅说明「哪一块是当前线型」，外圈给出的是同一件事的第二条线索，
  一深一浅一环三条线索，弱视用户也不必只靠颜色分辨。

**不在改动范围内**：颜色色块（`[data-sue-color]`）与跟随文字色色块（`[data-sue-follow-color]`）的
选中态外观一个字都没动，它们的选中仍然只有那一圈指示色。

## 只能在真实思源里确认的部分

1. **打开面板时重建选区**：`applyDecoration` 里的 `restoreOffsets` 会重新设一次文本选区（每一次改动都会，
   打开面板这一次的落笔是第一次发生在「面板还没建起来」的时机）。思源的浮动工具栏是挂在 `selectionchange`
   上的，重新设同一段选区会不会让工具栏闪一下、要不要等一帧再建面板，只能在真机上看一眼。
2. **深浅两档线色的实际观感**：`--b3-theme-color` 与 `--b3-theme-color-lighter` 在思源深浅主题下的具体取值
   （以及用户自定义主题里这两个变量是否被改写）无法从代码判断，需要在两套主题下各看一眼，
   确认「选中更显眼、未选中更退后」在真实配色上成立。
3. **撤销键的禁用外观**：`opacity: 0.5` + `pointer-events: none` 的观感、以及 `pointer-events` 关掉之后
   在移动端（touchend 绑定）是否仍与浏览器 `disabled` 按钮一致，需要真机确认。
4. **思源自己的 `<u>` 的真实形态**：夹具按 `<u>text</u>` 摆；思源从 Markdown 重新渲染出来的标记可能带
   额外的属性或 class。脱除只看标签名与字符偏移，理论上都能覆盖，但真实形态值得挑一个真的按下过
   思源下划线按钮的文档验证一次（含 `<u>` 跨越多个行内元素的写法）。
5. **打开面板的落笔对浮动工具栏的视觉影响**：装饰被裹上之后那段文字的行高与基线可能变，
   工具栏是按打开那一刻的位置贴上来的；面板自己的摆放会重算（建面板在应用之后），工具栏不会。
