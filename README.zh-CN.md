# 下划线增强

[English](README.md)

在思源笔记的编辑器浮动工具栏中，分别设置 CSS `text-decoration` 的**下划线**与**上划线** —— 线型与颜色两个方向各自独立。

* 包名：`siyuan-underline-enhancement`
* 需要思源 3.8.6 及以上（`minAppVersion: 3.8.6`）
* 桌面端、桌面浏览器版与移动端 APP 均可用

## 功能说明

思源原生浮动工具栏只有一个下划线按钮，无法设置线型与颜色。本插件在浮动工具栏中增加一个**下划线增强**按钮，
点击后打开一个浮层面板，下划线与上划线分别设置：

* **开关**：分别开启或关闭下划线、上划线。
* **线型**：`solid`、`dashed`、`dotted`、`double`、`wavy` 五种。线型色块用真实的 CSS `text-decoration-style`
  绘制，不是图标字符。
* **颜色**：跟随文字颜色、10 个预设色块，或用取色器自定义。自定义色会在色块行里单独占一个色块，
  当前用的是哪个颜色始终看得见。
* **清除装饰**：移除选区内两个方向的全部装饰。
* **撤销**：把装饰退回**上一步**——退回你实际做的那一次，包括它动过的每一个块。
  它只覆盖当前这一次面板会话：面板关闭时栈会清空，更早的改动请用文档历史。
  记录里的块若在改动之后又被编辑过，那一条会被跳过，而不是覆盖你后来的输入。
* 每次改动都会实时预览到选区上，并以 300ms 防抖保存。上次用过的配置会被记住，下次选中未装饰的文字时
  作为面板的初值。
* 两个方向的开关默认值不同：下划线默认**开**，上划线默认**关**。方向关闭时它的线型行、颜色行与取色器
  都是禁用的 —— 要先打开该方向的开关才能改。
* 一个选区里的各区域若装饰并不一致，面板会在你点之前说明：改任意一项都会把整个选区统一成这一份配置。

装饰以 inline style 的形式写在 `<span>` 上，因此即使插件完全没有加载 —— 只读模式、发布服务页面，或在别处
打开该文档 —— 装饰依然正确渲染。当下划线与上划线的设置不同时，两个方向写成嵌套的两个 span（外层承载上划线、
内层承载下划线）；两者完全相同时合并为一个 span，用 `text-decoration-line: underline overline`。

## 安装

### 从集市安装

插件发布后：**设置 → 集市 → 已安装**，搜索「下划线增强」，点击**安装**，再启用即可。

### 手动安装

`{工作空间}` 指工作空间数据目录，**设置 → 关于** 里可以看到路径，默认安装下是 `~/SiYuan/data`。

1. 构建插件（`npm run build`）或下载发布归档。
2. 新建目录 `{工作空间}/data/plugins/siyuan-underline-enhancement/`。
3. 把构建产物复制进去，**平铺放置**，中间不要多一层 `dist/`：

   ```text
   {工作空间}/data/plugins/siyuan-underline-enhancement/
   ├── plugin.json
   ├── index.js
   ├── index.css
   ├── icon.png
   ├── preview.png
   └── i18n/
       ├── en.json
       └── zh-CN.json
   ```

4. 重启思源，在**设置 → 集市 → 已安装** 里启用插件。

发布归档（`package.zip`）里的文件就平铺在归档根目录 —— 另外还有两份 README —— 可以直接解压到插件目录。

## 用法

1. 在编辑器里选中文字，浮动工具栏出现。
2. 点击工具栏中的**下划线增强**图标。该图标出现在每个编辑器的工具栏上；选区里没有可装饰的目标时
   （比如在代码块里），点击不会有任何反应。
3. 在面板里分别设置**下划线**与**上划线**两个区块：开关、线型、颜色。
4. 点**清除装饰**移除两个方向，点**撤销**退回上一步。
5. 点击面板外部或按 `Esc` 关闭面板，关闭时会做最后一次保存。

选区可以跨段落、跨列表项、跨表格单元格，每个可编辑区域各自独立包裹。每个受影响的块单独保存一次，
跨块改动不依赖单次写入。列表项有一处例外：**紧凑列表**里若某项的文字直接挂在 `<li>` 下（项内没有段落），
该文字不构成可编辑区域，无法装饰；见 [docs/manual-verification.md](docs/manual-verification.md) 第 6 项。

## 已知限制

1. **导出会让装饰降级**。导出 Markdown / HTML / PDF 时，下划线降级为普通 `<u>` 标签，上划线、线型与颜色
   都会丢失。原因是思源的 Markdown 引擎（Lute）只保留 `color`、`background-color`、`font-family`、
   `font-size` 四种 inline style。此为思源导出管线的既定行为，非本插件缺陷。
2. **Ctrl+Z 撤销不了本插件的操作**。装饰是通过 `/api/block/updateBlock` 写入的，该接口不产生事务，
   思源的撤销栈看不到这一步。请改用面板的**撤销**按钮，或思源的文档历史。
3. **代码块不支持**。这与思源原生浮动工具栏一致 —— 它在代码块里同样不出现。
4. **改动的作用域是选中的那一段，不是整块**。应用、换设置与**清除装饰**都只动选区内的装饰；
   同一块里落在选区之外的装饰会原样保留。要改或要清它，得先把它选中。
5. **撤销只覆盖一次已记录的改动，且只在当前这次面板会话内**。一次改动动到的所有块按一次撤销一起退回；
   若其中某个块在改动之后又被编辑过，那条记录会被跳过。面板关闭时栈会清空 —— 也就是说，只有做出那次改动的
   面板还开着时，它才撤得回来。

只读模式与发布服务页面不算限制：插件在那里不注册工具栏按钮，但装饰是纯 inline style，仍然正确渲染。

## 开发

```bash
npm install       # 安装依赖（需要 Node.js >= 24）
npm run dev       # 监听构建，输出 ./index.js 与 ./index.css
npm test          # 跑单元测试（node:test）
npm run build     # 生产构建，输出 ./dist/ 与 ./package.zip
```

类型检查：

```bash
node node_modules/typescript/bin/tsc --noEmit
```

代码风格：

```bash
npm run lint          # ESLint，能自动修的就修
npm run format        # dprint
npm run format:check  # dprint，只报告不修改
```

真实实例上的验收清单（中英双语）：单测覆盖不到的部分 —— 渲染、导出、发布、只读、移动端、
重渲染之后的撤销、层叠顺序 —— 都在 [docs/manual-verification.md](docs/manual-verification.md) 里。

发布的是生产构建产物：`dist/` 是可直接加载的插件目录，`package.zip` 是同样这些文件去掉 `dist/` 前缀后的
归档，解压即可放进插件目录。
